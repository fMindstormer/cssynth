Match counts pixels whose color is within 8/255 per channel of the target. The human solutions come from two public GitHub repos and are written to be readable, not golfed. Top CSSBattle players are far shorter, so these lengths are a baseline, not a leaderboard. The first version was rendered on Linux, like the targets; the current results were rendered on macOS, whose Chromium draws some edges slightly differently (about 0.2% of pixels on average), so match scores across the two are not exactly comparable.

What changed since the first version

Outline polygons

Polygons used to come only from a region's convex hull, with at most five vertices, so a notched or many-sided figure was tiled from slivers. The search now also traces each region's outline, which may be concave, and simplifies it to 4–12 vertices; a clean-up move then drops vertices while that lowers the score. Missing Piece went from 1,887 to 336 characters, shorter than the human solution.

Gradient backgrounds

For striped pictures the compiler fits a hard-stop linear-gradient at any angle: every pixel is projected onto the gradient line, and dynamic programming picks the band boundaries that minimize wrong pixels plus a cost per stop. Shapes are then layered on top as before. 12 targets use one.

Exactly optimal shadow grouping

Choosing which shapes become box-shadows of which, together with a valid paint order, is now solved exactly with a constraint solver: each shape gets a paint position, shadows share their anchor's, and every pair that must stay in order needs strictly increasing positions unless they share a group. Of 25 targets with any grouping, it beat the greedy grouping on 7 (67 characters) and proved optimality on 23.

Scoring by code length

Every variant is now judged by one objective: characters + wrong pixels ÷ ρ. A clean-up pass drops shapes, snaps near-equal shapes to identical sizes so they can share CSS, and evens out sizes for the shorter padding form, keeping each move only if the objective improves. The shared style element also moved to the end of the document, unclosed, which saves 9 characters wherever it is used.

How it works

  1. Palette. Find the flat colors and assign each pixel to one. A color that sits between two others counts as antialiasing only if it forms thin lines; a solid patch of it is a real fill.
  2. Base layer. A flat background color, or for striped pictures a hard-stop linear gradient fitted at any angle.
  3. Layered search. Repeatedly add the shape that fixes the most wrong pixels: a box with any corner radii, an ellipse, a rotated bar, or a polygon clipped with clip-path, fitted to the region's convex hull or traced from its outline, concave or not. A new shape can go at any depth in the stack, not just on top. That is how rings, eyes and other nested figures get built.
  4. Refine. Merge two pieces of the same color into one shape when that costs almost nothing, re-fit every shape against its final surroundings, drop shapes that no longer pay for their characters, and round coordinates where that changes no pixels.
  5. Code generation. A shape that is a shifted, uniformly grown or shrunk copy of another becomes a box-shadow of it, when the paint order allows and CSS keeps the shape exact (a spread larger than the corner radius bends the corners). The grouping and the paint order are chosen together by an exact solver. Boxes are sized with unitless padding (allowed in quirks mode), saturated corner radii get short spellings like 7em, and properties shared by every element move into one rule in a trailing, unclosed <style>.
  6. Choose. Nine search settings run per image; each result is cleaned up for length and scored by characters + wrong pixels ÷ ρ. The lowest score wins.

Limits of this prototype

  • No borders, text or filters yet, and gradients only on the background, so targets built from those come out longer or less exact.
  • The search is greedy with local refinement, so it can miss a cleverer decomposition that a golfer would see.
  • Colors are reproduced exactly; the code does not trade color accuracy for shorter color names.
  • My rasterizer's antialiasing differs slightly from Chromium's on long diagonal edges, which costs about a point of match on the striped flags.
